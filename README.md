# ฮองเรียน (HongRian) — เรียนคอร์สออนไลน์เป็นภาษาไทย

<img src="extension/icons/icon128.png" width="72" align="right" alt="">

สำหรับคนที่ซื้อคอร์ส Udemy ไว้แล้วแต่ฟังภาษาอังกฤษไม่ทัน

เปิดวิดีโอแล้วซับไทยขึ้นเอง แปลด้วย AI ที่เข้าใจบริบทโปรแกรมมิ่ง ไม่ใช่แปลคำต่อคำ
ทำงานบนเครื่องคุณทั้งหมด

**รองรับ Udemy และ YouTube** — YouTube ได้เฉพาะซับกับเสียงพากย์
ส่วนบทความ แบบทดสอบ และการแปลล่วงหน้าทั้ง Section เป็นของ Udemy อย่างเดียว

## รองรับบทเรียน 4 แบบ

| แบบ | ทำอะไรให้ |
|---|---|
| **วิดีโอ** | ซับไทยขึ้นทับบนวิดีโอ ตามจังหวะเสียง + พากย์ไทยได้ (Udemy / YouTube) |
| **บทความ** | แปลทั้งหน้า คงหัวข้อ รายการ และโค้ดไว้เหมือนเดิม |
| **แบบทดสอบ** | เติมคำแปลไทยใต้คำถาม ตัวเลือก และคำอธิบายเฉลย |
| **ไฟล์แนบ** | แปล PDF / DOCX / TXT / MD / HTML ที่ดาวน์โหลดมา |

### ปุ่มควบคุมในแถบเครื่องเล่น

ไม่ต้องเปิด popup ของส่วนขยาย — มีปุ่ม **ไทย** เพิ่มเข้าไปใน**แถบควบคุมของตัวเล่น**
ข้างปุ่มเดิมของเว็บ (ทั้ง Udemy และ YouTube) ไม่มีอะไรลอยทับวิดีโอ

กดแล้วเปิดเมนูขึ้นด้านบนเหมือนเมนูตั้งค่าของตัวเล่นเอง ข้างในมี:

- **ซับบนวิดีโอ** — ปิด / ไทย / ไทย + ต้นฉบับ และขนาดตัวอักษร
- **พากย์เสียงไทย** — เปิดปิดได้ทันทีระหว่างดู พร้อมบอกว่าใช้เสียงอะไรอยู่
- **เริ่มทันที / แม่นยำ** — เมื่อใช้เสียง Seamless (ดูหัวข้อถัดไป)
- เลือกเครื่องมือเสียงและเสียง ปรับความดังทั้งสองฝั่ง ตั้งเพดานการเร่งเสียง
- สั่งแปลใหม่ / แปลทั้ง Section · กด Esc เพื่อปิดเมนู

ตัวปุ่มมีจุดสีเขียวเมื่อมีอะไรเปิดอยู่ จึงดูออกได้โดยไม่ต้องเปิดเมนู

ทุกอย่างที่ตั้งในเมนูนี้ถูกบันทึกไว้ที่เดียวกับ popup ทั้งสองที่จึงไม่มีทางไม่ตรงกัน

> ถ้าหาแถบควบคุมไม่เจอ (เว็บเปลี่ยนโครงสร้าง) ปุ่มจะไปโผล่มุมขวาล่างของวิดีโอแทน
> เป็นทางสำรองเพื่อไม่ให้ควบคุมอะไรไม่ได้เลย ไม่ใช่ดีไซน์หลัก

### เริ่มทันที หรือ แม่นยำ — เลือกได้เมื่อใช้เสียง Seamless

ซับไทยแปลโดย AI ที่อ่านทั้งบทและใช้คลังศัพท์ของคอร์ส จึงแม่นแต่ต้องรอ
ส่วน Seamless แปลและพูดไทยจากต้นฉบับได้เองทันที แต่แปลตรงตัวกว่า
(เช่น "greeting string" ได้ "เส้นคำต้อนรับ" ขณะที่ AI ได้ "ข้อความทักทาย")

| | เริ่มทันที | แม่นยำ |
|---|---|---|
| วิดีโอเล่นเมื่อ | ทันที (เมื่อโมเดลเสียงพร้อม) | AI แปลล่วงหน้าครบ 90 วินาที |
| ซับช่วงแรก | คำแปลด่วนของ Seamless (สีจาง มีป้าย "แปลด่วน") | คำแปล AI |
| เสียงช่วงแรก | Seamless แปลและพากย์จากต้นฉบับ | อ่านคำแปล AI |
| หลังจากนั้น | ซับและเสียงเปลี่ยนเป็นคำแปล AI ทีละประโยคเมื่อแปลเสร็จ | เหมือนเดิม |

ทั้งสองโหมด AI แปลซับเบื้องหลังเสมอ เสียงอื่น (Edge, Google, OmniVoice, Windows)
แปลเองไม่ได้ จึงใช้แบบ "แม่นยำ" เสมอ

### โหมดแม่นยำ: วิดีโอถูกพักไว้ระหว่างแปล แต่ไม่ต้องรอทั้งบท

เปิดบทเรียนใหม่แล้วจะมีกล่องกลางจอบอกว่ากำลังทำอะไรถึงไหน และกันไม่ให้วิดีโอเล่นไปก่อน
เพราะนาทีแรกที่ดูไปโดยไม่มีซับคือนาทีที่เสียเปล่า

**แต่มันไม่รอจนแปลจบทั้งบท** — เซิร์ฟเวอร์ทยอยส่งผลออกมาทีละช่วง พอมีซับพร้อม
**ล่วงหน้า 90 วินาที**จากจุดที่คุณอยู่ วิดีโอก็เล่นต่อได้เลย ที่เหลือแปลเติมเบื้องหลัง
กล่องจะบอกด้วยว่าตอนนี้พร้อมไปกี่วินาทีแล้ว

ที่วัดจากจุดที่ดูอยู่ ไม่ใช่นับจำนวนบรรทัด เพราะช่วงต่างๆ แปลเสร็จไม่เรียงลำดับ —
ถ้าช่วงกลางเสร็จก่อนแต่คุณอยู่ต้นคลิป ก็ยังไม่ปล่อย และถ้าเหลือคลิปไม่ถึง 90 วินาที
แต่แปลครบถึงท้ายแล้วก็ปล่อยเลย ไม่รอเวลาที่ไม่มีทางมี

ถ้าเซิร์ฟเวอร์ค้าง กดปุ่ม **ข้ามการรอ แล้วดูไปก่อน** ได้ ไม่มีทางติดอยู่ในหน้าที่กดอะไรไม่ได้

> ใช้ได้กับ `--engine agy` (ค่าเริ่มต้น) ส่วน `--engine claude` ยังส่งผลออกมาทีเดียวตอนจบ

### กรณีที่มีซับไทยอยู่แล้ว

Udemy มีซับไทยสองชนิด ซึ่งคุณภาพต่างกันมาก เครื่องมือนี้แยกให้ (YouTube ใช้กติกาเดียวกัน):

- **คนแปล** (`manual`) → **ไม่แปลซ้ำ** แจ้งให้คุณกด CC เลือกไทย เพราะดีกว่า AI
- **เครื่องแปลอัตโนมัติ** (`auto`) → **แปลใหม่ให้** เพราะมันคือแปลด้วยเครื่องซ้อนบนถอดเสียงด้วยเครื่อง
  error ทบสองชั้น เช่นถ้าถอดเสียง "async" ผิดเป็น "a sink" มันจะแปลเป็น "อ่างล้างจาน" อย่างซื่อสัตย์

## สิ่งที่เครื่องมือนี้ไม่ทำ

- ❌ ไม่ดาวน์โหลดวิดีโอจาก Udemy
- ❌ ไม่ถอดเสียงจากวิดีโอ — บทเรียนต้องมีซับอังกฤษอยู่ก่อน
- ❌ ไม่ทำงานกับคอร์สที่คุณยังไม่ได้ซื้อ

## วิธีใช้หลัก — Chrome Extension

**[🚀 คู่มือติดตั้งแบบง่าย (เริ่มที่นี่)](INSTALL.md)** · [คู่มือแบบละเอียด](docs/install-extension.md)

สรุปสั้น ทำครั้งเดียวจบ:

1. ดับเบิลคลิก **`install.cmd`** — ติดตั้ง Python packages ให้ครบเอง
2. เปิด `chrome://extensions` → เปิด **Developer mode** → **Load unpacked** → เลือกโฟลเดอร์ `extension`
3. ทุกครั้งที่เรียน: ดับเบิลคลิก **`start-server.cmd`** เปิดค้างไว้ แล้วเปิดบทเรียนได้เลย ไม่ต้องกด CC

ครั้งแรกของแต่ละบทใช้เวลาแปล 30 วินาที - 2 นาที ครั้งต่อไปขึ้นทันทีจาก cache

### เสียงพากย์ไทย

เปิดสวิตช์ **พากย์เสียง** ได้จากแผงบนวิดีโอ เลือก engine ได้ 4 แบบ
— **[รายละเอียดทั้งหมดที่ docs/voices.md](docs/voices.md)**

| engine | ฟรีไหม | ต้องเตรียมอะไร |
|---|---|---|
| **edge** — Microsoft Azure Neural | ไม่จำกัด | `pip install -r requirements.txt` เท่านั้น **(แนะนำ)** |
| **windows** — เสียงใน Windows | ไม่จำกัด | ไม่ต้องเตรียมอะไร แต่ cache ไม่ได้ |
| **google** — Chirp 3 HD | 1 ล้านตัวอักษร/เดือน | บัญชี Google Cloud + service account JSON |
| **seamless** — Meta SeamlessM4T | ไม่จำกัด | GPU + `transformers`, `torch`, `soundfile` (โมเดลพากย์เสียงสไตล์ Facebook Reels) |
| **omnivoice** — รันในเครื่อง | ไม่จำกัด | GPU + `pip install omnivoice soundfile` |

`edge` กับ `windows` **คือเสียงเดียวกันเป๊ะ** (Niwat / Premwadee = Azure Neural)
ต่างกันแค่ `windows` สร้างเสียงในเบราว์เซอร์ จึง cache ไม่ได้และเตรียมล่วงหน้าไม่ได้
ถ้าจะดูคอร์สยาวๆ ให้ใช้ `edge`

`omnivoice` รันโมเดลในเครื่องด้วยการ์ดจอ ไม่ส่งข้อมูลออกไปไหนเลย และ**โคลนเสียงผู้สอนได้**
ถ้าใส่ไฟล์เสียงตัวอย่างไว้ 5-10 วินาที

รายการ engine ไม่ได้ฝังอยู่ในส่วนขยาย แต่ถามจากเซิร์ฟเวอร์ — ติดตั้ง engine เพิ่มที่ฝั่ง
Python แล้วมันจะโผล่ในตัวเลือกเอง

ขณะพากย์ ปรับเสียงผู้สอนและเสียงพากย์ได้จากแผงบนวิดีโอหรือจาก popup
เสียงจะหยุด/เริ่มใหม่ตามการ pause, seek และเปลี่ยนบทเรียน

**เสียงพากย์ไม่ได้ไล่ตามซับทีละบรรทัด** — cue ของซับคือชิ้นส่วนสำหรับแสดงผล
(สามสี่คำ ตัดกลางประโยคให้พอดีจอ) ถ้าพากย์ตามนั้นตรงๆ จะได้เสียงกระท่อนกระแท่น
และถูกตัดกลางคำทุกบรรทัด เพราะประโยคไทยพูดนานกว่าอังกฤษเสมอ

ระบบจึงรวม cue กลับเป็นประโยคก่อน แล้วค่อยพากย์ทีละประโยค โดย:

- **ไม่ขัดประโยคที่กำลังพูด** ประโยคถัดไปรอจนจบก่อนเสมอ
- **เร่งความเร็วให้พอดีช่วงเวลา** โดยคิดจากเวลาที่เหลือจนถึงประโยคถัดไป
  ไม่ใช่แค่ถึงตอนซับหาย (ผู้สอนหยุดหายใจระหว่างประโยค — เวลานั้นใช้ได้)
  เพดานเริ่มต้น 1.6x ปรับได้ในแผงตั้งค่า
- **โหลดเสียงล่วงหน้าไว้ 4 ประโยค** และถอดรหัส MP3 รอไว้เลย เพื่อไม่ให้เริ่มพูดช้า

### ความเร็วในการแปล

ครั้งแรกของแต่ละบทต้องรอจริง เพราะแปลด้วย AI ในเครื่องคุณ ไม่ได้ส่งไปเซิร์ฟเวอร์ใคร
สิ่งที่ทำไว้เพื่อลดเวลารอ:

- **แปลหลายช่วงพร้อมกัน** — บทเรียนยาวถูกแบ่งเป็นช่วงๆ ซึ่งไม่ได้พึ่งพากัน
  จึงรันพร้อมกัน 3 ตัว (เดิมเรียงทีละตัว) ปรับได้ด้วย `set UDTH_PARALLEL=5`
  แต่แต่ละตัวคือ `agy` หนึ่ง process จึงกิน RAM ตามจำนวน
- **ซับใช้ effort ระดับ medium** ส่วนเอกสารกับข้อสอบยังใช้ high
  ซับคือประโยคพูดสั้นๆ การคิดหนักไม่ได้ทำให้ดีขึ้นเท่าที่เสียเวลาไป
  (ถ้าตั้ง `--effort low` ไว้เอง ระบบจะไม่ไปเพิ่มให้)
- **แปลทั้ง Section ล่วงหน้า** — วิธีที่ได้ผลที่สุด ดูหัวข้อถัดไป
- **โหมดเร็ว (เฉพาะ `--engine claude`)** — ใช้โมเดลเล็กที่เร็วกับซับ

  ```cmd
  set UDTH_FAST=1
  ```

  ซับจะใช้ Haiku 4.5 ($1/$5 ต่อล้าน token) ส่วนเอกสารกับข้อสอบยังใช้ Opus เหมือนเดิม
  เพราะสองอย่างนั้นอ่านละเอียดและมีโค้ดกับคำถามสอบอยู่ข้างใน
  เปลี่ยนโมเดลเองได้ด้วย `set UDTH_FAST_MODEL=claude-sonnet-5`

  นี่คือวิธีเดียวกับที่เครื่องมือเสียเงินใช้ให้รู้สึกว่าเร็ว — โมเดลเล็ก ไม่ใช่เวทมนตร์

> เครื่องมือแบบเสียเงินที่เร็วกว่านี้มักส่งข้อความไปแปลที่คลาวด์ของเจ้าของบริการ
> โปรเจกต์นี้เลือกทำงานในเครื่องทั้งหมด — ช้ากว่าในครั้งแรก แต่ไม่มีใครเห็นว่าคุณเรียนอะไร
> ไม่มีค่ารายเดือน และดูซ้ำกี่ครั้งก็ไม่ต้องแปลใหม่

### แปลทั้ง Section ล่วงหน้า (ไม่ต้องรอทีละบท)

เปิดบทเรียนบทใดก็ได้ใน Section ที่จะเรียน → กดไอคอนส่วนขยาย → **แปลทั้ง Section นี้ล่วงหน้า**

ส่วนขยายจะไล่เก็บวิดีโอและบทความทั้ง Section ส่งเข้าคิวให้เซิร์ฟเวอร์แปลรวดเดียว
พอเรียนไปถึงบทถัดๆ ไป คำแปลรออยู่ใน cache แล้ว ไม่ต้องรออีก

- ระหว่างแปลจะมีกล่องสถานะที่**มุมซ้ายล่าง**ของหน้า Udemy บอกว่าเหลืออีกกี่บท
- **เปลี่ยนบทเรียนหรือปิดกล่องได้เลย** คิวอยู่ที่เซิร์ฟเวอร์ ไม่ได้อยู่ที่หน้าเว็บ
- บทที่กำลังเปิดดูอยู่จะได้รับสิทธิ์แซงคิวเสมอ ไม่ต้องรอคิวเบื้องหลังให้จบก่อน
- บทที่แปลไว้แล้วจะถูกข้าม และบทที่มีซับไทยที่คนแปลไว้แล้วก็จะถูกข้ามเช่นกัน
- แบบทดสอบไม่รวมอยู่ในคิวนี้ (บางชุดมีถึง 250 ข้อ) เปิดหน้าแบบทดสอบแล้วมันจะแปลให้เอง

> ⚠️ ทุกครั้งที่แก้โค้ด extension ต้องกดรีเฟรชการ์ดที่ `chrome://extensions`
> **แล้วกด F5 ที่หน้า Udemy ด้วย** ไม่งั้นจะขึ้นว่า "ส่วนขยายเพิ่งถูกอัปเดต"

```cmd
python -m unittest discover -s tests -v
node --test tests/
```

ทดสอบตัวแยกซับ (SRT / VTT / แผง transcript ของ Udemy), ตัวสร้างไฟล์ซับ, คลังศัพท์ และเซิร์ฟเวอร์ (รวมด้านความปลอดภัย)
ไม่ต้องต่ออินเทอร์เน็ต ไม่ใช้ `agy` และไม่เขียนทับคลังศัพท์หรือ cache ของคุณ

### ความปลอดภัยของเซิร์ฟเวอร์ในเครื่อง

เซิร์ฟเวอร์ฟังที่ `127.0.0.1` เท่านั้น และ**ยอมรับเฉพาะคำขอจากส่วนขยายนี้** (Origin ต้องขึ้นต้นด้วย
`chrome-extension://`) กับเครื่องมือบรรทัดคำสั่งอย่าง curl ที่ไม่ส่ง Origin หน้าเว็บทั่วไปที่คุณเปิดอยู่
จะสั่งแปลหรือสร้างเสียงไม่ได้ (ได้ 403) และคำขอที่ใช้ชื่อ Host แปลกปลอมก็ถูกปฏิเสธเช่นกัน
(กัน DNS rebinding) ถ้าเปลี่ยนไปเรียกจากเครื่องมืออื่นที่ส่ง Origin มาเอง ต้องแก้ `origin_allowed` ใน `udemy_th/server.py`

### จัดระเบียบคลังศัพท์

```cmd
python -m udemy_th glossary --tidy --json out\glossary-cards.json
```

รวมคำซ้ำ (`Array.from` กับ `Array.from()`, `BOM` หลายรูปแบบ) และตัดคำที่ไม่ใช่ศัพท์โปรแกรม
(เช่น `speed`, `sign in`) โดยสำรองไฟล์เดิมเป็น `glossary/glossary.backup-<วันที่>.json` ให้ก่อนเสมอ
`--json` ส่งออกเป็นไฟล์สำหรับทำแฟลชการ์ด

## วิธีใช้รอง — CLI

### แปลไฟล์แนบ

ดาวน์โหลดไฟล์แนบจาก Udemy ตามปกติ แล้ว **ลากไฟล์มาวางบน `translate-docs.cmd`**

หรือสั่งเอง:

```bash
python -m udemy_th docs "C:\Downloads\slides.pdf"
python -m udemy_th docs "C:\Downloads\course-handouts"   # ทั้งโฟลเดอร์
```

ได้ไฟล์ `.th.md` ใน `out/docs/` — ไฟล์โค้ด zip และรูปภาพจะถูกข้ามอัตโนมัติ

### สร้างไฟล์ซับ `.srt` เก็บไว้

ใช้เมื่ออยากได้ไฟล์ซับไปเปิดใน VLC หรืออยากได้สรุปบทเรียนเก็บไว้อ่าน

```bash
# ก๊อป transcript จาก Udemy (ปุ่ม Transcript) แล้ว...
python -m udemy_th go                          # อ่านจาก clipboard เลย
python -m udemy_th go courses/my-course/       # หรือทำทั้งโฟลเดอร์รวดเดียว
```

หรือดับเบิลคลิก **`translate-clipboard.cmd`** / **`translate-course.cmd`**

ได้ไฟล์ใน `out/<คอร์ส>/<บท>/`:

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `<บท>.dual.srt` | ซับอังกฤษ + ไทย **(แนะนำ)** |
| `<บท>.th.srt` | ซับไทยอย่างเดียว |
| `<บท>.summary.md` | สรุปบทเรียน + อธิบายโค้ด + ศัพท์ในบทนี้ |

## คำสั่งทั้งหมด

```bash
python -m udemy_th go [ไฟล์|โฟลเดอร์]   # ทำครบทุกขั้นในคำสั่งเดียว (เว้นว่าง = clipboard)
python -m udemy_th docs <ไฟล์|โฟลเดอร์>  # แปลไฟล์เอกสารแนบ
python -m udemy_th serve                # เปิดเซิร์ฟเวอร์ให้ extension ใช้
python -m udemy_th glossary             # ส่งออกคลังศัพท์เป็น Markdown
python -m udemy_th status               # ดูว่าบทไหนแปลถึงไหนแล้ว
```

แยกทีละขั้น (เมื่ออยากตรวจงานระหว่างทาง):

```bash
python -m udemy_th prepare <ไฟล์ transcript>
python -m udemy_th translate <โฟลเดอร์งาน>
python -m udemy_th build <โฟลเดอร์งาน>
```

ตัวเลือกที่ใช้บ่อย:

| ตัวเลือก | ความหมาย |
|---|---|
| `--engine claude` | ใช้ Claude API แทน Antigravity |
| `--effort low` | แปลเร็วขึ้น ใช้กับบทที่ไม่ยาก |
| `build --bom` | เขียน `.srt` แบบ UTF-8 with BOM (แก้ไทยเพี้ยนใน VLC) |
| `go --force` | แปลใหม่ทับของเดิม |

## จุดเด่น: คลังศัพท์ทำให้คำแปลสม่ำเสมอทั้งคอร์ส

ทุกครั้งที่แปล ศัพท์เทคนิคที่เจอจะถูกเก็บลง `glossary/glossary.json`
แล้วบทเรียนถัดไปจะถูกป้อนคลังศัพท์นี้กลับเข้าไปก่อนแปล

ผลคือ `closure` ในบทที่ 40 ถูกแปลด้วยคำเดียวกับบทที่ 3 ไม่ใช่คนละคำทุกบทแบบ Google Translate
และคุณได้คลังศัพท์ไว้ทบทวนก่อนสอบหรือสัมภาษณ์เป็นของแถม

```bash
python -m udemy_th glossary --course "JavaScript Masterclass"
# -> glossary/glossary.md ตารางศัพท์ทั้งหมดพร้อมคำอธิบายไทย
```

กติกาการแปลที่ตั้งไว้: **ศัพท์เทคนิคคงคำอังกฤษ** (`async`, `endpoint`, `middleware`)
พร้อมใส่คำอธิบายไทยในวงเล็บครั้งแรกที่เจอ ส่วน**ชื่อไฟล์ ชื่อคลาส ชื่อเมธอด และโค้ด
ห้ามแปลเด็ดขาด** เพราะคุณต้องพิมพ์ตามได้จริง

## ทำงานยังไง

```
เปิดบทเรียนใน Udemy
   │
   ├─► ถาม Udemy API ว่าบทนี้ชนิดอะไร มีซับภาษาอะไรบ้าง
   │      │
   │      ├─ มีซับไทยที่คนแปล ──► แจ้งให้กด CC แล้วหยุด
   │      │
   │      └─ ไม่มี / มีแต่ auto ──► ดึงไฟล์ WebVTT อังกฤษมาทั้งไฟล์
   │                                      │
   ▼                                      ▼
แสดงซับไทยทับวิดีโอ  ◄────  เซิร์ฟเวอร์ในเครื่องคุณ (127.0.0.1:8765)
      ▲                                   │
      └──── cache บนดิสก์ ◄──── AI แปล + ใช้คลังศัพท์เดิม
```

**ทำไมต้องถาม API แทนการอ่านซับจากหน้าเว็บ:** ทดสอบกับหน้าจริงแล้วพบว่า Udemy
ไม่ได้ใช้ TextTrack มาตรฐานของ HTML5 (`video.textTracks` ว่างเปล่าทั้งที่ซับกำลังแสดงอยู่)
มันโหลดไฟล์ WebVTT มาวาดเอง แถมล้าง performance buffer ทิ้ง การไปไล่ดักไฟล์จึงไม่น่าเชื่อถือ

**cache ผูกกับ lecture id จาก URL** ไม่ใช่ชื่อบทเรียน เพราะ Udemy ทยอยเติมชื่อลงหน้าเว็บทีหลัง
อ่านเร็วไปได้ค่าหนึ่ง อ่านช้าไปได้อีกค่าหนึ่ง ถ้าใช้ชื่อเป็นกุญแจจะแปลใหม่ทุกครั้งที่กลับมาดู

**คิวทำงานทีละงาน** ไม่ใช่ยิงพร้อมกัน เพราะการแปลทั้ง Section คือการสั่งงานสิบกว่างานรวดเดียว
ถ้าปล่อยขนานกันจะได้ `agy` สิบกว่าตัวแย่งเครื่องกัน และแย่งกันเขียนไฟล์คลังศัพท์เดียวกันด้วย
บทที่ผู้ใช้กำลังเปิดดูจะถูกยกระดับความสำคัญให้แซงคิวเบื้องหลังเสมอ

**การเก็บบทเรียนทำที่หน้าเว็บ ส่วนการแปลทำที่เซิร์ฟเวอร์** เพราะการขอไฟล์ซับจาก Udemy
ต้องใช้ cookie ที่ล็อกอินไว้ ซึ่งมีอยู่เฉพาะในหน้าเว็บ พอส่งเข้าคิวแล้วงานอยู่ที่เซิร์ฟเวอร์
จะเปลี่ยนบทเรียนหรือปิดแท็บก็ไม่กระทบ

**ส่วนที่ต่างกันของแต่ละเว็บถูกแยกไว้ใน adapter** (`extension/sites.js` สำหรับ YouTube,
`extension/sites/udemy.js` สำหรับ Udemy) ส่วนที่เหลือ — ซับ พากย์เสียง เมนู การพักวิดีโอ —
จึงไม่รู้เลยว่ากำลังรันอยู่บนเว็บไหน การเพิ่มเว็บที่สามคือการเขียน adapter ตัวใหม่

**ซับและเสียงอ่านจากไทม์ไลน์ประโยคชุดเดียว** (`core/timeline.js`) แบ่งประโยคจากต้นฉบับครั้งเดียว
แต่ละประโยคมีคำแปลสองระดับ: `final` (AI) และ `draft` (Seamless แปลด่วน) ของ final แทน draft เสมอ
การตัดสินว่าจะพักหรือเล่นวิดีโอมีที่เดียวคือ state machine ใน `pipeline/session.js`
รายละเอียดการออกแบบ: [docs/design/dubbing-v2.md](docs/design/dubbing-v2.md)

**YouTube ต้องมี PoT (Proof of Origin Token) ถึงจะยอมส่งไฟล์ซับ** ยิง `baseUrl` เปล่าๆ
จะได้ HTTP 200 พร้อม**เนื้อหาว่าง** ไม่ใช่ error ทำให้ดูเหมือนวิดีโอไม่มีซับทั้งที่มี

token คำนวณเองไม่ได้ แต่มันติดอยู่ใน query string ของทุกคำขอที่ตัวเล่นยิงเอง
`extension/pot-interceptor.js` จึงรันใน world ของหน้าเว็บตั้งแต่ `document_start`
แล้วห่อ `XMLHttpRequest.open` กับ `fetch` ไว้ เพื่อส่งต่อ `pot` ที่เห็นผ่าน DOM event
(ไม่ได้บล็อกหรือแก้คำขอใดๆ เรียกของเดิมด้วยอาร์กิวเมนต์เดิมเสมอ)

ถ้ายังไม่เคยเห็น token เลย จะ**กดปุ่ม CC ของ YouTube ให้หนึ่งครั้ง** เพื่อบังคับให้ตัวเล่น
ยิงคำขอออกมา แล้วกดกลับเป็นสถานะเดิม สุดท้าย URL ที่ใช้ต้องมีทั้ง `&pot=` และ `&c=WEB`

**รายการซับอ่านจากตัวเล่นโดยตรง** ผ่าน `chrome.scripting` ที่รันใน world ของหน้า
เรียก `movie_player.getPlayerResponse()` ซึ่งตรงกับคลิปที่โหลดอยู่จริงเสมอ
ดีกว่าขุด `ytInitialPlayerResponse` จาก HTML ที่ค้างอยู่ตั้งแต่โหลดหน้าแรก

**Udemy ระบุส่วนของตัวเล่นด้วย `data-purpose`** เช่น `[data-purpose="video-control-bar"]`
ห้ามอิงชื่อ class เพราะมันมี hash ต่อ build แล้วเปลี่ยนทุกครั้ง

### ข้อควรรู้ถ้าจะแก้ไฟล์ `.cmd`

ไฟล์ `.cmd` ทุกไฟล์ **ต้องเป็น ASCII ล้วน ห้ามมีภาษาไทย** แม้แต่ในบรรทัด `REM`

cmd.exe อ่านไฟล์ batch ผิดตำแหน่งเมื่อในไฟล์มีไบต์ที่ไม่ใช่ ASCII ขณะที่ console
อยู่ที่ code page 65001 (UTF-8) ผลคือมันหลุดไปรัน "เศษ" ของบรรทัดถัดไปเป็นคำสั่ง
แล้วขึ้น error แปลกๆ แบบนี้:

```
'emy_th' is not recognized as an internal or external command
```

ข้อความภาษาไทยที่ผู้ใช้ต้องเห็น ให้พิมพ์จากฝั่ง Python แทน (Python จัดการ UTF-8
ได้ถูกต้อง) ตัว `.cmd` ตั้ง `PYTHONIOENCODING=utf-8` ไว้ให้แล้ว

## หมายเหตุเรื่องลิขสิทธิ์

เครื่องมือนี้ประมวลผลเนื้อหาของคอร์สที่ **คุณซื้อแล้ว** บนเครื่องคุณเอง เพื่อให้คุณเข้าใจ
บทเรียนที่จ่ายเงินไปแล้ว ไฟล์ทั้งหมดอยู่ในเครื่อง ไม่ได้ส่งไปเผยแพร่ที่ไหน

**สิ่งที่ไม่ควรทำ:** แจกจ่ายไฟล์ซับ สรุปบทเรียน หรือคำแปลข้อสอบให้คนอื่น
เพราะเนื้อหาบทเรียนเป็นลิขสิทธิ์ของผู้สอน ไม่ใช่ของคุณ

`.gitignore` ในโปรเจกต์กันโฟลเดอร์ `cache/` `out/` `work/` `courses/` `glossary/`
ไม่ให้ถูก commit อยู่แล้ว แต่ถ้าคุณย้ายไฟล์ไปวางที่อื่น ให้ดู `git status` ก่อน commit ทุกครั้ง
